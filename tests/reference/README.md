# YM2413 reference trace provenance

`emu2413-trace.txt` was generated by compiling the original MIT test driver
`emu2413-trace.c` with the unmodified C synthesis model at
[digital-sound-antiques/emu2413 a1d5120903b75f93d3eb7690e34a29c0b4add903](https://github.com/digital-sound-antiques/emu2413/tree/a1d5120903b75f93d3eb7690e34a29c0b4add903).
This is an independent execution of upstream C, not output recorded from our Rust
implementation. It validates the adaptation; shared upstream assumptions do not
establish physical-chip accuracy. Additional analytic sine/volume tests are
independent of that model.

The driver includes upstream `emu2413.c` to call its native clock/72 update
routine, avoiding its sample-rate converter. It instantiates a fresh YM2413 for
each preset/drum, uses 72 clocks between address and data and 144 clocks after
each data write, warms up a stated number of internal samples, and prints 32
signed integer samples per row. Presets 0–15 each have held and released rows;
then five rows exercise rhythm bits 0–4 individually. Further rows cover all nine
key-on transients, combined AM/PM/feedback/scaling, live custom updates, sustain
and entry/exit of rhythm mode. Only currently active voice outputs are summed,
excluding upstream's stale inactive channel buffers after a mode switch.
All writes and warmup counts
are visible in the driver. `preset-0` is a custom sine with a silent modulator.
No masking, panning, host interpolation or analog filters enter these traces.

Tolerance is **zero integer units**: native-rate synthesis uses integer tables
and arithmetic in both implementations. Floating-point mix scaling is tested
separately. Tests use `include_str!` and need no downloads/compiler at runtime.

Reproduce from the repository root (downloads are optional validation tooling):

```sh
trace_dir=$(mktemp -d)
for file in emu2413.c emu2413.h LICENSE; do
  curl -fsSL "https://raw.githubusercontent.com/digital-sound-antiques/emu2413/a1d5120903b75f93d3eb7690e34a29c0b4add903/$file" -o "$trace_dir/$file"
done
cc -O2 -I"$trace_dir" tests/reference/emu2413-trace.c -lm -o "$trace_dir/trace"
"$trace_dir/trace" > "$trace_dir/result.txt"
cmp tests/reference/emu2413-trace.txt "$trace_dir/result.txt"
```

## Missing-path regression sensitivity

Run `python3 tests/reference/missing-bus.py` to create a temporary source tree,
retain the new installation APIs needed for test setup, and replace the entire
Hardware Bus implementation with the verbatim evaluation-baseline version
`c54482e0153ad15db8e79888c81258515e085169`. The script requires that commit locally.
It runs two new integration tests and requires assertion failures (compilation
failures do not count). This isolates the baseline's missing mapping and port
paths without modifying production files or pretending the optional installation
API existed before this change.

Observed results: the Z80 diagnostic's exact RAM assertion received six zeros
instead of `01 08 57 65 FF A5`; the active-FM assertion received only silence.
Both tests pass with the implemented bus. This check was executed locally.
